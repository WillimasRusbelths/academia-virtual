## T038: puerto y adaptador implementados

`enrollment/public/materials-access.ts` publica MaterialsEnrollmentAccess,
MaterialsEnrollmentDecision, MaterialsEnrollmentScope y referencias mínimas.
El puerto no expone pg, SQL, Buffer o Nest. Sus dos operaciones son:

- hasAccess(studentId, groupId, decision): boolean para una matrícula propia
  cuyo confirmedAt ≤ decision.at < validUntil original.
- groups(studentId, decision): referencias únicas y ordenadas groupId/courseId
  de matrículas propias vigentes, sin datos económicos o de otros alumnos.

`enrollment/infrastructure/materials-participant.ts` liga el participante al
PoolClient recibido y a la capacidad viva de su coordinador. assertDecision
comprueba identidad/vigencia antes del SQL; use conserva la comprobación de vida
durante el await. El bigint se convierte a parámetro PostgreSQL con el transporte
exacto existente de matrícula, sin Date. Se leen únicamente filas de Enrollment,
sin reconstruir límites a partir del período actual, filtrar por catálogo/docente,
consultar pagos/órdenes, abrir otra transacción, adquirir locks o escribir finanzas.
El resultado no autoriza por sí solo sesión, estado del material o cancelación.

`materials-enrollment-participant.spec.ts` contiene diez casos con el reloj SQL
aislado existente y el coordinador real. ADMIN solo proporciona una unidad de
trabajo real en estas pruebas del participante: no se simula autorización STUDENT
ni se amplían permisos de gestión. Se verifican seis límites ±1 µs, reserva/pago/
incidencia/historial/grupo ajeno, oferta retirada/docente inhabilitado/período
ampliado, token falso/caducado y ausencia de conexión/transacción/locks adicionales.
Se observa el query real del mismo cliente: solo dos SELECT sobre Enrollment.
Cada caso compara fingerprint financiero antes/después, aun ante fallo.

Antes de implementar el adaptador, diez casos fallaron: la comprobación explícita
de capacidad ausente dentro del callback fue normalizada por el coordinador a
indisponibilidad segura. El informe conserva ese resultado; no hubo imports rotos,
setup SQL fallido o omitidos. Después de agregar los dos archivos de producto,
los mismos diez tests aprobaron sin modificar sus expectativas. T035/T036 se
conservan intactas: su rojo de integración aún corresponde a T039–T042.
