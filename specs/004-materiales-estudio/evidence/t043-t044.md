# T043/T044 — cliente binario y pantalla de alumno

Fecha: 2026-11-16, America/Lima. Se implementan la capacidad de descarga del
cliente HTTP y la pantalla/controlador de materiales del alumno. **44/68 tareas
completadas, 24 pendientes**. T045 conserva la integración desde matrículas y
rutas/ciclo de cuenta; T046 conserva el E2E alumno con backend real.

## Cliente y límites de confianza

`BinaryDownloadClient` es una capacidad opcional inyectable desde app. Solo
`GET /materials/items/:uuid/content` puede descargar binario. La petición JSON
no puede consumir esa ruta y download no puede invocar uploads u otra familia.
Se mantienen same-origin, credentials same-origin, no-store, redirect error,
AbortController y el presupuesto de generación compartido con JSON/upload.
Los ámbitos anidados conservan tanto cancelación de cuenta como de operación.

La descarga requiere status 200, longitud decimal canónica de 1–20 000 000,
PDF/JPEG/PNG, attachment con fallback ASCII y filename* UTF-8 seguro/coherente.
Se exigen no-store/nosniff/no-referrer; se rechazan Content-Range, Location, ETag,
compresión o respuesta redirigida. Después de consumir el Blob se comprueban
nuevamente generación/aborto, longitud y tipo. No se analiza contenido exitoso
como JSON ni se entrega un resultado parcial, 206/304 o un cuerpo incompatible.

Los errores conservan únicamente códigos/campos del contrato y mensajes locales
seguros. 401 expira la sesión compartida una vez, sin reintento. Una respuesta
tardía, incluso durante lectura de Blob o decodificación de error, no puede afectar
la generación nueva. El cliente no crea URLs ni guarda bytes en almacenamiento.

El lector de DTO acepta las dos proyecciones cerradas reales del backend. La
minimal del alumno no admite autor, revisión, estado, bytes, hash o claves extra.
La pantalla de gestión estrecha explícitamente a su audiencia antes de usarla;
una proyección minimal no se convierte por cast en datos de gestor. Una aserción
previa de test se estrecha con `revision in item` y conserva la misma igualdad.
Las expectativas originales de T037 permanecen intactas.

## Pantalla y ciclo de recursos

`createMaterialsStudentController` tiene un ámbito por cuenta/grupo; combina
AbortController, generación y comprobación tras cada await. Carga contexto y
página, distingue LOADING/READY/EMPTY/ERROR/AUTH_REQUIRED/DENIED/DISPOSED y no
presenta un error como listado vacío autorizado. Paginación y reintento son
manuales y realizan una nueva consulta. Carga nueva descarta contexto/listado y
URL anterior; 401/403/404 también los eliminan.

Solo una referencia de la lista vigente inicia descarga y solo una operación
binaria corre a la vez. Además del transporte, el controlador contrasta tamaño,
tipo y nombre con el material listado antes de crear la URL. Se revoca al usar,
reemplazar, recargar o desmontar. Una liberación tardía de un enlace viejo no
revoca uno nuevo; dispose es idempotente. Ningún resultado tardío crea una URL.

`MaterialsStudentPage` muestra grupo/curso, título, descripción escapada,
PDF/JPEG/PNG, bytes y fecha UTC con microsegundos. Usa botones y enlace download
nativos, región perceptible y foco tras errores/archivo recibido. «Descargar»
recibe el archivo y luego ofrece «Guardar archivo»; solo ese éxito anuncia el
archivo recibido. La liberación tras uso se agenda después de la acción del
enlace, sin impedir el guardado nativo. No hay visor, porcentajes ficticios,
contenido HTML ejecutable o datos de gestión.

Se exporta también un componente de montaje del ámbito. App debe suministrar en
T045 la clave nueva por cuenta/grupo y conectarlo desde las matrículas. En este
bloque no se modifican las rutas de producción ni sus permisos de gestores.
