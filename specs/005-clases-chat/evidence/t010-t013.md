# T010–T013 — Permisos y participantes de clases

2026-11-18, America/Lima. Base `59b78ff`, rama `feat/005-clases-chat`.
[Resultados y hashes](t010-t013-results.json). El bloque verifica participantes
y permisos por separado; no entrega gestión/chat ni autoriza aún un aula completa.

- **T010**: permisos `classes:manage-all` para ADMIN, `classes:manage-own` para
  TEACHER y `classes:participate-enrolled` para STUDENT. Políticas cerradas de
  gestión/participación en SessionPermission y SessionLookup, sin aceptar arrays
  arbitrarios, dominios mezclados, orden distinto, huecos o permisos desconocidos.
  Las políticas de materiales conservan su forma y comportamiento.
- **T011**: [puerto de oferta](../../../apps/api/src/modules/academic-offering/public/classes-access.ts)
  y [participante](../../../apps/api/src/modules/academic-offering/infrastructure/classes-participant.ts).
  Descubre referencias y proyecta grupo/curso/estados/responsable/elegibilidad
  actuales, sobre la misma conexión titular. ADMIN conserva referencias históricas;
  TEACHER solo las asignaciones actuales no canceladas. Retirada no es cancelación.
  La proyección de alumno evita consultar elegibilidad docente; esta no es fuente
  del derecho propio de matrícula. Descubrimiento no concede autorización.
- **T012**: [puerto de matrícula](../../../apps/api/src/modules/enrollment/public/classes-access.ts)
  y [participante](../../../apps/api/src/modules/enrollment/infrastructure/classes-participant.ts).
  Lee solo referencias/derecho de Enrollment con token exacto del titular y scope
  activo: `confirmedAt <= t < validUntil`, sin redondear a Date o recalcular el
  período de oferta. hasAccess sirve también para el alumno objetivo de moderación;
  cuenta/rol, pertenencia de clase y cancelación los comprobará T014. Reservas,
  pendientes, incidentes, historia y descubrimiento futuro no se convierten en
  matrícula vigente. No muta, bloquea o proyecta datos de pagos.
- **T013**: [puerto de autores](../../../apps/api/src/modules/users/public/class-authors.ts)
  y [adaptador](../../../apps/api/src/modules/users/infrastructure/class-authors.ts).
  Solo `id/name/role` actuales para referencias previamente autorizadas por un
  scope activo. SQL parametrizado y mapeo explícito, sin UserView/correo/estado,
  roster o endpoint global. Lote vacío no consulta usuarios, capacidad expirada
  falla, entradas inválidas se rechazan antes de SQL y errores BD usan texto seguro.

## Verificación

Se reutiliza el [harness aislado](implementation-environment.md), con datos
ficticios, owner/runtime separados y esquemas aleatorios, sin puertos publicados.
Las fuentes se montan en solo lectura; la aplicación manual no se inicia ni migra.

Las 31 pruebas nuevas de permisos se escribieron antes de ampliar la matriz.
La ejecución inicial produjo 22 aprobadas y **9 fallos funcionales** por permisos
positivos/políticas ausentes, sin fallos de import/configuración ni omisiones.
Después pasaron **840/840 unitarias**, incluidas las de arquitectura y los permisos
anteriores, y **52/52 integraciones** entre participantes nuevos, permisos de oferta
y el participante de matrícula de materiales existente. No son las 3.182 pruebas
de integración completas del checkpoint anterior.

El cierre enfocado aprueba **60/60** casos: 31 unitarios nuevos de permisos,
23 integraciones de sesiones/oferta/matrícula y 6 de proyección de autores.
También pasa generación Prisma, lint, build y tipos de ambas suites. Este cierre
incluye arrays con huecos rechazados y ambas consultas de matrícula tras expirar
el scope; sus hashes de fuentes se registran en resultados.

Las [pruebas de participantes](../../../apps/api/tests/integration/classes-participants.spec.ts)
verifican acceso permitido/denegado con sesiones PostgreSQL reales, datos actuales,
lecturas de cambios sin confirmar desde el mismo cliente y ausencia de BEGIN/locks
financieros dentro de los participantes. Cubren comienzo/fin ±1 μs, fechas originales,
otro alumno/grupo, objetivo de moderación, token ajeno/inválido y capacidades caducas.
Cada caso compara la huella completa de datos financieros antes y después.
Las [pruebas de autores](../../../apps/api/tests/integration/classes-author-projection.spec.ts)
comprueban proyección mínima, nombre/rol actuales, conexión titular, referencia
ajena, UUID inválido/desconocido, vacío, expiración y error seguro.

no sustituyen la autorización real de clases. Los 40 casos T009 conservan su
pendiente de T014/T017: no se repiten ni se marcan aprobados por este bloque.

y la composición; no se excluye esa suite de CI y se conserva el commit local.

ledger/errores, video no configurado y composición, con revalidación de T009.

reglas financieras, specs cerrados 001–004, configuración manual o evidencias
anteriores. Sin 006/007, compras, publicación, emisiones o aceptación de capacidad.
Los servicios de ensayo se detienen conservando su volumen al cerrar el bloque.
